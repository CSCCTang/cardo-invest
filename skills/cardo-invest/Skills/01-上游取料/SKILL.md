# 01 · 上游取料

## 1. 职责

把「Office 输入 + 上游机读 JSON」装成引擎可直接消费的工作目录，并产出一份**财务输入底表**与缺项表：

```text
输入文件/ → 过程文件/00-总控/引擎项目/（04_成果报告 + 05_过程/{AHP,低空解析,投资决策}）
         → 财务输入.json（cardo/finance-input/v1）+ 缺项表.md + 取料清单.json
```

**只收不猜**：上游有 → 取用并记来源；没有 → `gaps[]` + 占位，链不中断。

## 2. 输入

| 输入 | 路径 | 说明 |
|---|---|---|
| 现状分析报告 | `输入文件/` 任意层级 `*现状分析报告*.docx` | 原样搬运；自动剔除上游自带的「（数据来源：…）」标注行 |
| 现状分析报告（结构化） | `04_成果报告/` 或 `输入文件/` 任意层级 `*现状分析*.docx|.md` | `extract_upstream.py` 按 H1/H2 分节 + 抽表格 → `05_过程/投资决策/上游摘要.json`（正文与工程量表的事实底稿） |
| AHP 权重 | `输入文件/` 任意层级 `*AHP权重表*.xlsx`（退而 `*权重表*.xlsx`） | 读「导出值」表：准则权重/局部权重/综合权重；xlsx 优先，`过程文件/00-总控/上游机读件/权重表.json` 仅兼容兜底 |
| AHP 评分 | `输入文件/` 任意层级 `*AHP方案评分结论*.xlsx` | 读「排序与评级」「指标得分明细」两表，抄录得分/贡献/评级 |
| AHP 结论 | `输入文件/` 任意层级 `*AHP权重与评分结论*.docx` | 只读一致性表（CR/λmax/是否通过），不复算 |
| 低空现状指标 | `输入文件/` 任意层级 `*现状指标*.json`（兼容 `过程文件/00-总控/上游机读件/现状指标.json`） | **只消费 json**；`现状指标.xlsx` 仅登记留档、不解析，缺 json 时第 3 章指标表会缺 |
| 现状事实库 | `输入文件/` 任意层级 `事实库.json`（兼容 `过程文件/00-总控/上游机读件/现状事实库/*.json`） | 登记存在；从 CardoStatus 的 `过程文件/05-事实抽取与事实库/facts/事实库.json` 复制来 |
| 手动槽位 | `输入文件/` 任意层级 `*槽位*.xlsx` 或 `上游机读件/槽位.json` | 功能定位/业态/时序/组织/运营/改造思路 |
| AHP Office 成果 | `输入文件/` 任意层级 `AHP*.xlsx/.docx` | 人读留档，只登记进取料清单（`action=reference`），不解析、不重算 |
| 财务参数 | `输入文件/` 任意层级 `*财务参数*.xlsx` | **唯一必需输入**；取费/收入/税率/资金结构 |
| 上游摘要 | `…/05_过程/投资决策/上游摘要.json` | 现状分析报告的分节正文 + 事实 + 槽位（供 05 取料；**可研是成果，不作输入**） |

**投递区规则**：不分类、不限层级；文件/文件夹/zip 都可以直接放，脚本递归发现并按文件名关键词归类，
zip 自动解包到 `过程文件/00-总控/输入解包/`。缺件时按 `missing[].suggestion` 在对话里说明替代方案。

`财务参数.xlsx` 表结构（按表名定位，列名见脚本表头映射）：

| 工作表 | 列 |
|---|---|
| 项目 | 项目名称、项目方向、改造面积(㎡)、建设期(年)、运营期(年)、折现率、土地使用税计税面积(㎡) |
| 工程费 | 编号、名称、金额(万元) |
| 其他费 | 编号、名称、金额(万元) 或 取费基数(万元)+费率 |
| 预备费 | 预备费率 |
| 建设期利息 | 借款额(万元)、年利率、建设期年数、半额计息(是/否)、建设期融资费用(万元)（给了就直接采用，不按利率反推） |
| 收入 | 编号、名称、年均收入(万元) 或 单价+数量+计费天数/月数、增值税率、年增长率 |
| 成本 | 班组人数、人均年薪酬(万元)、福利系数、年增长率 |
| 资金结构 | 资本金(万元)、借款(万元)、补助(万元)、借款年利率、借款期限(年)、宽限期(年)、还款方式、财务评价投资基数(万元) |
| 可研财务指标 | 指标、值、单位、说明（全部投资/资本金 FIRR·FNPV·回收期 + FNPV 折现率）；报告表位 1/2 优先采用 |

## 3. 输出

| 产物 | 路径（相对工作区） |
|---|---|
| 引擎工作目录 | `过程文件/00-总控/引擎项目/` |
| 取料清单 | `过程文件/01-上游取料/取料清单.json`（{schema, placed[], missing[], status}） |
| 财务输入底表 | `过程文件/01-上游取料/财务输入.json`（`cardo/finance-input/v1`） |
| 缺项表 | `过程文件/01-上游取料/缺项表.md` |

`财务输入.json` 关键块：`project / estimate / revenue / cost / tax / finance / profit`、`slots`、`ahpWeights`、
`ahpScores`、`upstream`、`rules`、`sources[]`、`placeholders[]`、`ruleChecks[]`、`gaps[]`。
每个 gap 必须四要素齐全：`code / what / need / owner`（`where` 为补到哪）。

## 4. 命令

```powershell
# 工作区根
python Skills/01-上游取料/scripts/prepare_inputs.py --workspace . [--scenario full|gaps] [--no-timestamp]
python Skills/01-上游取料/scripts/collect_inputs.py --project-dir 过程文件/00-总控/引擎项目 --no-timestamp
```

退出码：`prepare_inputs` 0 装配完成；2 工作区不合法；**3 缺财务参数（待补）**。
`collect_inputs` 0 成功（有 gaps 也是 0）；1 输入坏；2 项目目录无法识别。

## 5. 闸门

1. `gaps[]` 每条都有 `code/what/need/owner`；
2. AHP 权重文件不存在时，`ahpWeights.temporary=true` 且 `kind=default`（临时权重必须显式标注）；
3. 财务参数缺失 → exit 3，不拿经验值顶替；
4. 缺上游时可以继续（gaps 分支），但不得出现"先估后补"的数值。

## 6. 规则

1. **不补数**：缺工程量/单价 → 缺项，不填行业经验值、不引用相似项目数字。
2. **不重算 AHP**：准则/指标权重与方案得分原样取自 AHP 成果；判断矩阵未随「导出值」提供时，按权重派生展示矩阵并在 provenance 注明。
3. **来源可追**：每个取到的值在 `sources[]` 记 `{field, source:{file,locator,quote}, kind}`。
4. **只读输入**：不改任何外部工作区与 `输入文件/` 原件；报告 docx 只剔除机读标注行（不改正文、不改数）。
5. **路径相对**：不写盘符，也不配置任何外部路径；一切输入只看本工作区 `输入文件/`。

## 7. 本地实现修正（与单技能版本的差异）

- `collect_inputs.py` 数值扫描跳过 `slots.*`：否则 `operationModel` 的 "ratio" 会被误判为比率字段（假 gap）。
- `prepare_inputs.py` 固定 docx/xlsx 的 zip 时间戳，保证两次跑字节一致。

## 8. 调优点

- 换项目：整包替换 `输入文件/`（现状报告 + AHP 三份 + 低空 + 槽位 + 财务参数），路径与脚本都不用改。
- 改取费/收入口径：只改 `输入文件/财务参数.xlsx`，然后 `pipeline.py run --from 01`。
- 缺项话术：改 `collect_inputs.py` 的 `GAP_META`；口径数字：改 `规则/财务口径.yaml`（改则版本 +1 并全链回归）。
