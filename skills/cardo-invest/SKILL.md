# CardoInvest · 投资决策流水线

一个文件夹就是这条流水线：独立使用时把 `CardoInvest/` 整个放进用户的项目文件夹；插件方式下它已装在技能目录里，**不用安装、不用配置**。

**独立工作区、独立交付**：一个包一个工作区、一份交付；四包放同一目录不会自动串联，也不共用状态文件。
跨包只靠产物交接——把上游产物复制进本包 `输入文件/`（任意层级）：现状分析报告 docx、`事实库.json`、`现状指标.json`、AHP 权重/评分 xlsx。
**只认 json**：`现状指标.xlsx` 仅人读留档、不解析，缺 `现状指标.json` 时第 3 章指标表会缺。
判断 vs 实测的分工与单会话自足要求，见《Cardo 四包通用规范》（`交付规范/Cardo四包通用规范.md`）。

**交互节奏（插件版，四步）**：
1. **进场先建目录**：第一次调用先跑 `python "<技能目录>/scripts/cardo.py"`，它会把 `输入文件\`、`过程文件\`、`成果文件\` 等目录建好（幂等，已存在不覆盖），并逐条说明每个目录放什么——把这段说明原样转给用户。
2. **建完就停**：没有输入文件不开工。缺料时说清缺什么、放到哪个目录，等用户放好再继续。
3. **岔口让用户拍板**：选方案、定口径、改参数、跳步这类判断，一次只问一个，摆出可选项请用户选，不替用户默认。
4. **用户回「继续」后再跑**：材料到位后重跑 `python "<技能目录>/scripts/cardo.py"` 往下走。

**放料清单**：`开工.py` 会在工作区生成 `放料清单.md`，列出要什么、放哪、现在到没到；本文档是执行细则。
**首次运行自动备依赖**：缺依赖就在用户缓存（`%LOCALAPPDATA%\cardo\venv-invest`）按 `requirements.txt`
建虚拟环境并安装（阿里云→清华→USTC→官方源回退），之后复用；技能包目录保持只读。
需本机已装 Python 3.9+。

**技能包只读**：本文件夹里的 `SKILL.md`、`开工.py`、`requirements.txt`、`Skills/`、`assets/` 在开工过程中一个字节都不会被写；
运行期状态只写工作区与用户缓存。
工作区默认取**当前目录**（插件方式；独立使用时是本文件夹的上一级目录，如 `XX项目/`）：`输入文件/` 放料、`过程文件/` 留痕、`成果文件/` 出活，
`工作区参数.json` 和 `.cardo/`（虚拟环境）也在那里。换项目时把技能文件夹整体拷走即可，不会带走任何项目数据。

在项目文件夹里执行命令（`--workspace` 可显式指定别的工作区）：

```powershell
python "<技能目录>/scripts/cardo.py"
```

## 先看放料清单

首次运行 `开工.py` 会在工作区根目录生成 **`放料清单.md`**：按项列出「要什么 / 放哪儿（绝对路径）/ 怎么命名 / 是否必需 / 现在到没到」，
每次运行都会刷新。想一项一项确认，就跑：

```text
python "<技能目录>/scripts/cardo.py" --intake
```

它会一项一项问（回车=已放好，s=暂时没有，q=退出），并在你确认后**立即复扫**，没真的放进去不会放行；必需项缺失则停在这一步。

## 开工三步

1. **收料**（硬门槛只有一项）：用 `输入文件-模板/财务参数-空白.xlsx`（首次运行自动释放）按可研/估算附表填写，
   另存为 `输入文件/财务参数.xlsx`——9 张表齐全，**工程费至少 1 行（名称 + 金额）**。
   其他可选件直接丢进 `输入文件/` 任意层级：现状分析报告、AHP 权重/评分、低空现状指标（**只认 json**，xlsx 仅留档）、可研、槽位表。
2. **问清一件事**：项目全称（`--project`）；若「项目」表里已填「项目名称」，会自动登记，可不问。
3. **开工**：

```powershell
python "<技能目录>/scripts/cardo.py"
python "<技能目录>/scripts/cardo.py" --project "项目全称"        # 项目名不从表里自动登记时
python "<技能目录>/scripts/cardo.py" --check                    # 只校验输入与参数，不跑流水线
```

`开工.py` 每次运行都会：依赖自检（缺就建 `.cardo/venv-invest`，按 阿里云 → 清华 → USTC → 官方源 回退安装）→ 建目录 → 校验模板 sha
→ 校验财务参数表结构与工程费是否填 → 调 01→08。续跑用 `--from <步>`（如 `--from 01`），不要从头重跑。

关键口径：

- **只有财务参数是硬门槛**。没填到可用就停，**不用经验值顶替**。

- 金额单位万元；费率/利率/增长率填小数（8% → 0.08）。
- 文件、文件夹、zip 都可直接放 `输入文件/` 任意层级，01 自动解包发现。

## 缺料怎么办（三选一）

1. **登记缺口**（默认）：写进缺项表，并由 08 导出内部件《待确认清单》；成品正文只写有依据的内容，不编造、不写降级话术。
2. **线下补**：说清要哪张表/哪个字段、找谁拿、放进 `输入文件/财务参数.xlsx`。
3. **联网检索补**：跑 `python "<技能目录>/scripts/cardo.py" --research`，生成
   `过程文件/00-总控/网络补料/补料清单.md`（工程费单价、费率、LPR、税率、资本金比例的检索方向）与 `网络补料.json`。
   - 检索结果回填 `网络补料.json`：`key / value / unit / source_url / publisher / date`；查不到写 `not_found: true`。
   - 落位：复制 `输入文件-模板/财务参数-空白.xlsx` 为 `输入文件/财务参数.xlsx`，逐格填「参考值」，在备注写机构 + URL + 取价日期（LPR 必须写取价日）；拿不准留空，01 会登记缺口。
   - 未经用户确认的检索值只能作参考，不得当已确认参数。

## 章节成文：确定性成文（2026-11-14 定稿）

**本包不启用大模型回填**，05 一律走确定性成文。

理由：确定性成文可控、可复核、可复现——每个数字都能回指 `依据对照表.json` 的登记来源，
07 的 E-7 逐值核对才有意义。接入大模型回填等于把已跑通的同源链路换成不可控文本，
评审稿的风险不值这个便利。故 05 不再生成「写作任务包」，`分章初稿_待回填/` 路径已废弃。

成文纪律（写死在 `assemble_chapters.py`）：

- 数字只照抄 `投资估算.json` / `财务测算.json` / `方案比选.json`，不改写、不推算；
- 有据的写实，并把口径写在同一句里（「台账口径」「按资金申请口径测算」）；
- 取不到的指标**整句、整行不写**，不用「暂按同类项目推定」凑字数；
- 需业主确认的事项不进正文，由 08 导出内部件《待确认清单》；
- 正文不出现「推断/推理/待核实」类工作底稿标注，出处只进 `依据对照表.json`。

### 财务指标口径（2026-10-30 补）

- 建议书里的财务指标**一律是本报告按《财务参数.xlsx》测算的结果**。
- 「可研财务指标」表填的可研对照值**不覆盖**测算值，只在 **8.4 与可研财务指标对照**表并列展示；
  两者差异超限时自动登记缺项 `FIN-REF-DIFF`，并在正文写明「正式申报前须统一口径」。
- 原因：早前两套值会同时出现在报告里（表位 1 与敏感性分析表各一套 FIRR），
  读者无从判断哪套是本报告结论；且对账若拿可研值做基准，篡改测算结果也照样通过。
- 所以：**改了《财务参数.xlsx》的收入/成本/折现率/资金结构后，以本报告测算值为准**；
  可研值不同就说明两边输入口径不同，先核对再定。
