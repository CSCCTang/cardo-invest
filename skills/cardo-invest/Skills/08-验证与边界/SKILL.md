# 08 · 验证与边界

## 1. 职责

三件事，顺序执行：

```text
export_office.py      过程 JSON → 成果文件/{投资估算,财务评价,方案比选}.xlsx（只格式化，不二次计算）
independent_verify.py 独立复算 + 基线对账 + 成品回读 + 边界扫描 → 独立验证结果.json / 产物指纹.json
```

**独立**指：不 import 引擎 `_lib`、不调用 `calc_*` 函数、不读模板结果单元格；只读过程 JSON 与成品文件。

## 2. 输入 / 输出

| 方向 | 路径 |
|---|---|
| 读 | `过程文件/01-上游取料/财务输入.json`、`02-匡算/投资估算.json`、`03-财务评价/财务测算.json`、`04-三方案比选/方案比选.json`、`05-章节成文/分章/` |
| 读 | `成果文件/成品版/项目投资决策建议书/项目投资决策建议书.docx|.pdf`（回读章/表/占位/数字/版式） |
| 读 | `输入文件/` 任意层级 `AHP权重表.xlsx`（独立读「导出值」表，与引擎 AHP 权重逐项对账） |
| 读 | `记忆与规则/验证基线-CardoInvest.json`（可删） |
| 写 | `成果文件/内部件/{投资估算,财务评价,方案比选,待确认清单}/<同名>.xlsx`；`成果文件/内部件/AHP/{AHP权重表,AHP方案评分结论}.xlsx`（表 10-1 附件 5—6 的实物副本） |
| 写 | `过程文件/08-验证与边界/{Office导出清单,独立验证结果,产物指纹,成品闸门报告}.json` |
| 写（`--baseline write` 或首次 auto） | `记忆与规则/验证基线-CardoInvest.json` |

## 3. 命令

```powershell
python Skills/08-验证与边界/scripts/export_office.py --workspace .
python Skills/08-验证与边界/scripts/independent_verify.py --workspace . --baseline auto|write|check|none
python Skills/08-验证与边界/scripts/final_gates.py --workspace .
```

退出码：`export_office` 0 成功 / 2 缺过程产物；`independent_verify` 0 全过 / 1 有失败项 / 2 输入缺失；
`final_gates` 0 全过 / 1 有违规（交付结构、成品版式、缺口词、三源同源、政策文号）。

**缺口词口径（2026-11-14）**：G3 除「未提资/暂缺/待补/未提供/请提供/待补充/资料缺失/缺项/待定/待核实」外，
再拦「暂按/推定/测算假设/需业主确认/待业主/待确认/推断/需现场核实/同类项目通行」——
成品是评审稿，不许出现「我没资料」的姿态。取不到的数整句不写，需业主确认的进内部件《待确认清单》。
豁免只走**字段级白名单**（`FIELD_WHITELIST`）：正文出现「影像纹理采样推定」时，只有上游
`现状指标.json#diagnostics.texture` 被显式标为 `derived: true` 才不计缺口词；取不到标记照常拦。
不存在「扫描前按字符串删除」的做法。附件文件名（带 .xlsx/.docx/.pdf 等扩展名的片段）视为结构串，
不参与缺口词计数；正文句子里的同名词照常计数。

## 4. 独立复算口径（写死在脚本，与 `规则/验证口径.yaml` 同值）

| 项 | 口径 |
|---|---|
| 工程费/其他费 | `Σ amount`，其他费支持 `取费基数 × 费率`；缺项则合计不可信（不补 0） |
| 预备费 | `(工程费 + 其他费) × 预备费率` |
| 建设期利息 | `Σ(当年提款 × 年利率 × 0.5)`，**不计复利** |
| 总投资 | 工程费 + 其他费 + 预备费 + 建设期利息 |
| IRR | 自实现二分（步长 0.0025，多根取最接近 10%） |
| FNPV | `Σ CFt/(1+r)^t`，t 从 1 起，`Decimal` |
| 回收期 | 累计首次转正年 − 1 + \|上年累计\|/当年净现金流 |
| ROE / ROI | 运营期年均净利润/资本金；运营期年均 EBIT/总投资 |
| ICR / DSCR | 运营期 ΣEBIT/Σ利息；(ΣEBITDA−Σ所得税)/Σ(还本+付息) |

容差：**成品** 0.04pp / 0.01 万元 / 0.01 年；**基线** 0.5% / 1 万元 / 0.5 年。

## 5. 检查项（60+ 项，分 8 组）

| 组 | 内容 |
|---|---|
| EST-* | 工程费/其他费/预备费/建设期利息/总投资独立复算 + 资金筹措平衡 |
| FIN-* | 两套现金流 FIRR/FNPV/PT 重算、ROE/ROI/ICR/DSCR 可复算、折现系数抽检 |
| SCH-* | 3 套方案、7 维度、排名连续、推荐 = 第 1、方案 FIRR 合理区间、口径标注 |
| AHP-* | 权重合计≈1、与用户拷入的 AHP xlsx 逐项一致（**未重算**）、第 9 章确实纳入 16 指标与 3 方案得分 |
| DOC-* | 10 章/章序、6 表、占位符 0、无盘符、项目名与工作区参数一致、表 1/2 数字与 JSON 一致 |
| CH-* | 分章 10 份、来源映射 ≥10 条、空来源 0、缺项标注计数 |
| BASE-* | 总投资/6 项指标/ROE/ROI/三方案得分/推荐方案对账 |
| BND-* | 输入白名单（docx/pdf/xlsx/pptx/json/zip，可散放/文件夹/压缩包）、成果仅 Office、Skills 白名单、过程产物无盘符、引擎目录不越界 |
| REF-* | 引擎自算值与可研对照值的口径一致性（差异超限时须已在成品显式披露） |

### 口径纪律（2026-10-30 补）

- **本报告指标一律取引擎自算值**（`财务测算.json#indicators`）。可研对照值
  （`财务输入.json#finance.referenceIndicators`）**不覆盖**引擎值，只在成品 8.4
  「与可研财务指标对照」表单列并标注差异。
  理由：早前 05/06/07/08 四处都做 reference 覆盖，导致同一份报告出现两套 FIRR
  （表位 1 写可研 3.24%、敏感性分析表写引擎 9.57%），读者无法判断哪套是本报告结论。
- 对账基准（`DOC-NUM-*`）取**引擎值**：若拿 reference 做期望值，就是「可研值对可研值」，
  篡改引擎计算结果也照样通过——独立复算形同走过场。
- `REF-CONSISTENT`：引擎值与可研值差异超限时，必须已在成品中显式披露（对照表 + 口径提示），
  否则判 fail。
- `运行日志.json` 是流水线的执行痕迹（含各步 stdout 与本机绝对路径），**不纳入**
  BND-PATH 的盘符扫描（按绝对路径豁免，不按目录名）。否则全链跑完再跑 08 必然自伤。


## 6. 基线怎么用

- `auto`（默认）：有基线 → 对账；无基线 → 用本次结果写入（首次使用）。
- `write`：口径变更后显式重写（**先确认变更已评审**）。
- `check`：必须存在，用于回归。
- `none`：只做结构自洽（`--scenario gaps` 时用，因为数值本就不同）。
