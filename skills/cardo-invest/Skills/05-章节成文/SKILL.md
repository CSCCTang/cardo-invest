# 05 · 章节成文

## 1. 职责

把前四步的过程 JSON + **上游摘要.json** + AHP 结果，写成 **10 章分章稿**（每段带"来源："行）。

取料红线（本 skill 的第一原则）：正文里每一个地名、机构名、面积、工程量、人数、金额、日期、文号，
都必须来自 `上游摘要.json` / `财务输入.json` / `投资估算.json` / `财务测算.json` / `方案比选.json`；
取不到写「（资料缺失：…，见缺项表）」并登记缺项。**可研是交付成果，不是输入**，本步骤不读可研。

| 章 | 标题 | 主要取料 |
|---|---|---|
| 1 | 项目概述 | 财务输入#project、上游摘要#facts（范围/性质/面积/工程量）、投资与财务结论 |
| 2 | 项目背景与建设必要性 | 上游摘要#sections（政策/概况/问题小节原文）、上游问题表 |
| 3 | 现状调研分析 | 上游摘要#sections（现状详细分析）、现状指标.json |
| 4 | 市场分析与功能定位 | 槽位（功能定位/业态）、财务测算#revenue、上游人口与商业结论 |
| 5 | 项目建设范围、改造内容与建设方案 | 上游摘要#facts（范围/四至/工程量）+ 上游工程量表 + 槽位（改造思路/时序） |
| 6 | 组织架构与运营模式 | 槽位（组织架构/运营模式）+ 财务测算#cost/revenue |
| 7 | 投资估算与资金筹措方案 | 投资估算.json |
| 8 | 财务评价 | 财务测算.json（表位 1/2） |
| 9 | AHP 量化分析 | 财务输入#ahpWeights（4 准则 / 16 指标 / 矩阵 / CR）+ 上游 AHP 评分表（逐方案逐指标得分、合成、评级、拉分项） |
| 10 | 附件清单 | 过程产物 + AHP 机读件（01 由成果 xlsx 转出）+ AHP 上游 Office 成果（存在才列） |

## 1.1 章节 skill（一章一 skill）

`assemble_chapters.py` 是共享分章引擎，一次落 10 章；随后由 10 个章节 skill 按 CH-01→CH-10 逐章复核，
每章契约已切到各自 `Skills/05-0X-<章名>/规则/章节契约.yaml`。总控顺序执行、一章不过不进下一章。

| 章 | skill | 复核命令（总控自动跑） |
|---|---|---|
| CH-01 | `05-01-项目概述` | `check_chapter.py --chapter CH-01` |
| CH-02 | `05-02-项目背景与建设必要性` | `--chapter CH-02` |
| CH-03 | `05-03-现状调研分析` | `--chapter CH-03` |
| CH-04 | `05-04-市场分析与功能定位` | `--chapter CH-04` |
| CH-05 | `05-05-项目建设范围、改造内容与建设方案` | `--chapter CH-05` |
| CH-06 | `05-06-组织架构与运营模式` | `--chapter CH-06` |
| CH-07 | `05-07-投资估算与资金筹措方案` | `--chapter CH-07` |
| CH-08 | `05-08-财务评价` | `--chapter CH-08` |
| CH-09 | `05-09-基于AHP层次分析法的投资决策指标体系量化分析` | `--chapter CH-09` |
| CH-10 | `05-10-附件清单` | `--chapter CH-10` |

章级复核只读：H1 逐字、来源行、字数、占位是否已登记缺项表；结果写
`过程文件/05-章节成文/分章自检/CH-0X.json`。

## 2. 输入 / 输出

| 方向 | 路径 |
|---|---|
| 读 | `…/05_过程/投资决策/{财务输入,投资估算,财务测算,方案比选}.json` |
| 读 | `…/05_过程/投资决策/上游摘要.json`（01 按 H1/H2 抽取的事实底稿；05 改写成建议书正文，不直接复制原文） |
| 读 | `…/05_过程/AHP/评分表.json`（01 从 AHP 成果 xlsx 抄录的排序/评级/逐指标得分，只引用不重算） |
| 读 | `规则/章节契约.yaml`、`规则/写作规范.yaml`、`规则/财务口径.yaml`（契约与版式依据） |
| 写 | `…/05_过程/投资决策/分章/CH-01..CH-10.md`、`分章/来源映射.json`、`缺项表.md` |
| 写（总控复制） | `过程文件/05-章节成文/分章/`、`来源映射.json`、`缺项表.md` |

## 3. 命令

```powershell
python Skills/05-章节成文/scripts/assemble_chapters.py --project-dir 过程文件/00-总控/引擎项目 [--no-timestamp]
```

退出码：`0` 成功；`2` 必需输入缺失/坏。

## 4. 闸门

1. `CH-01..CH-10` 十份齐全且非空；
2. 每节都有"来源：…"行；来源映射 ≥10 条、空来源 0；
3. 数字只取"首个运营年 / 运营期年均"口径，禁止把 33 年合计标成"年值"；
4. 缺项处显式写"（资料缺失，见缺项表）"，并进缺项表；
5. AHP 评分：上游有合成结果就引用（逐方案逐指标得分/合成/评级/拉分项），没有才占位；
6. 第 10 章引用的 AHP Office 成果文件名必须真实存在（由 `detect_workspace()` 动态探测，不写死）。

## 5. 规则

1. **数字只有一个来源**：正文数字来自 JSON，不手填、不复算第二套；
2. **逐段溯源**：来源具体到 JSON 字段/文件路径；
3. **不重算 AHP**：第 9 章的权重、指标权重、CR、评分合成全部引用上游；
4. **口径隔离提示**：9.2.4（上游 AHP 对同族三方案的专家评分）与 9.3（本报告投资口径三方案比选）
   同方案族、两套口径，本章显式提示"不得互相替代，正式申报前统一口径后二选一"；
5. **AHP 成果完整入册**：9.1.3 列全 16 项指标、9.2.2 列全 16 项子/综合权重、9.2.4.2 列三方案逐指标得分，
   第 10 章列 AHP 机读件与 Office 成果（仅引用，不重算）；
6. **只写本项目**：项目名取 `工作区参数.json#projectName`；地名/机构名只能来自上游摘要，成品不得出现外来专名（07/08 有扫描闸门）。

## 6. 本地实现修正（与单技能版本的差异）

- 新增 `load_upstream_scores(project)`：直接读 `05_过程/AHP/评分表.json` 的 `composite/rating/conclusion/topDrivers`，
  解决"上游评分存在但第 9 章仍显示缺项"的问题；原实现只认 `ahpWeights.scores`（取料不透出该键）。
- 9.1.3 / 9.2.2 / 9.2.4.2 由固定话术改为**按上游实际数据展开**（16 指标、16 权重、3 方案×16 得分）。
- 新增 `detect_workspace(project)`：第 10 章只列真实存在的 AHP 成果文件，避免附件清单虚列。
- 9.3 增加口径隔离提示行，避免与 9.2.4 的推荐结论冲突。
